# Working Artifact Specification v1.0

> Specification for canonical working artifacts stored in this repository.

## Purpose

Working artifacts preserve evolving analytical and strategic thinking before they become investor materials, spreadsheets, decks, or formal operating plans.

## Required Sections

A working artifact should generally include:

1. Purpose
2. Background
3. Core thesis
4. Definitions
5. Assumptions
6. Open questions
7. Implications for the financial model
8. Next actions

## Rules

- Keep original source materials separate from working interpretations.
- Do not overwrite source context when analysis changes.
- Record assumptions explicitly.
- Prefer small, reviewable Markdown files over large monolithic documents.
- Generated outputs belong under `build/`.
